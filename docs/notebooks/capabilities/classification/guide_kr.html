Claude로 하는 분류: 보험 지원 티켓 분류기¶

이 가이드에서는 보험 지원 티켓을 10개 범주로 분류하는 고정확도 분류 시스템을 만듭니다. 프롬프트 엔지니어링, 검색 증강 생성(RAG), 생각의 사슬 추론을 결합해 분류 정확도를 70%에서 95% 이상으로 단계적으로 끌어올리는 방법을 배웁니다.

이 가이드를 마치면 복잡한 비즈니스 규칙을 다루고, 학습 데이터가 부족한 상황에서도 동작하며, 설명 가능한 결과를 내놓는 분류 시스템을 설계하는 방법을 이해하게 됩니다.

사전 준비¶

  • Python 3.11 이상과 기본적인 친숙함
  • Anthropic API 키 (여기서 발급)
  • VoyageAI API 키 (선택 — 임베딩은 미리 계산되어 있습니다)
  • 분류 문제에 대한 이해

Claude로 하는 분류¶

대규모 언어 모델(LLM)은 분류 분야에 혁신을 가져왔습니다. 특히 전통적인 머신러닝 시스템이 어려움을 겪던 영역에서 그렇습니다. LLM은 복잡한 비즈니스 규칙이 얽힌 분류 문제, 그리고 학습 데이터의 품질이 낮거나 양이 적은 상황에서 눈에 띄는 성공을 거뒀습니다. 게다가 LLM은 자신의 판단에 대해 자연어로 설명과 근거를 제시할 수 있어 분류 과정의 해석 가능성과 투명성을 높여 줍니다. LLM의 힘을 활용하면 전통적인 머신러닝 접근을 넘어서는 분류 시스템을 만들 수 있고, 데이터가 부족하거나 비즈니스 요구가 복잡한 상황에서 특히 빛을 발합니다.

이 가이드에서는 고급 분류 작업에 LLM을 활용하는 방법을 살펴봅니다. 다음 핵심 구성 요소와 단계를 다룹니다.

  1. 데이터 준비: 먼저 학습 데이터와 테스트 데이터를 준비합니다. 학습 데이터로 분류 모델을 만들고, 테스트 데이터로 성능을 평가합니다. 분류 시스템의 효과를 보장하려면 데이터 준비가 중요합니다.

  2. 프롬프트 엔지니어링: 분류에 LLM의 힘을 끌어내는 데 프롬프트 엔지니어링이 결정적인 역할을 합니다. 분류에 사용할 프롬프트의 구조와 형식을 정의하는 프롬프트 템플릿을 설계합니다. 이 템플릿에는 사용자 질의, 범주 정의, 그리고 벡터 데이터베이스에서 가져온 관련 예시가 담깁니다. 프롬프트를 세심하게 설계하면 LLM이 정확하고 맥락에 맞는 분류를 생성하도록 이끌 수 있습니다.

  3. 검색 증강 생성(RAG) 구현: 분류 과정을 개선하기 위해 학습 데이터의 임베딩을 저장하고 효율적으로 검색하는 벡터 데이터베이스를 사용합니다. 벡터 데이터베이스는 유사도 검색을 가능하게 해, 주어진 질의에 가장 관련 있는 예시를 찾아 줍니다. 검색된 예시로 LLM을 보강하면 추가 맥락을 제공하고 생성되는 분류의 정확도를 높일 수 있습니다.

  4. 테스트와 평가: 분류 시스템을 만든 뒤에는 변환된 테스트 데이터로 성능을 엄밀하게 시험합니다. 테스트 질의를 순회하며 분류 함수로 각각을 분류하고, 예측 범주와 기대 범주를 비교합니다. 분류 결과를 분석해 시스템의 효과를 평가하고 개선할 지점을 찾아냅니다.

평가 프레임워크¶

분류기를 만들기 전에 성능을 측정할 평가 프레임워크를 준비하겠습니다. 두 개의 핵심 함수를 만듭니다.

  1. evaluate(X, y, classifier, batch_size): 속도를 위해 동시 실행으로 모든 테스트 예시에 분류기를 돌린 뒤 정확도 지표를 계산하고 혼동 행렬을 생성합니다. batch_size 파라미터가 동시 API 요청 수를 제어합니다.

  2. plot_confusion_matrix(cm, labels): 혼동 행렬을 시각화해 어떤 범주끼리 혼동되는지 보여 주어, 분류기가 어디서 어려움을 겪는지 파악하게 해 줍니다.

이 프레임워크 덕분에 여러 분류 방식을 경험적으로 비교하고, 전체 정확도뿐 아니라 어떤 범주가 까다로운지도 이해할 수 있습니다.

요청 한도: MAXIMUM_CONCURRENT_REQUESTS의 기본값은 1입니다. 더 높은 등급이라면 이 값을 늘려 평가 속도를 높일 수 있습니다. 등급별 한도는 요청 한도 문서를 참고하세요.

import concurrent.futures

import matplotlib.pyplot as plt
import numpy as np
from sklearn.metrics import classification_report, confusion_matrix

MAXIMUM_CONCURRENT_REQUESTS = 5


def plot_confusion_matrix(cm, labels):
    # Visualize the confusion matrix
    fig, ax = plt.subplots(figsize=(8, 8))
    im = ax.imshow(cm, cmap="Blues")

    # Add colorbar
    ax.figure.colorbar(im, ax=ax)

    # Set tick labels and positions
    ax.set_xticks(np.arange(len(labels)))
    ax.set_yticks(np.arange(len(labels)))
    ax.set_xticklabels(labels, rotation=45, ha="right")
    ax.set_yticklabels(labels)

    # Add labels to each cell
    thresh = cm.max() / 2.0
    for i in range(len(labels)):
        for j in range(len(labels)):
            ax.text(
                j,
                i,
                cm[i, j],
                ha="center",
                va="center",
                color="white" if cm[i, j] > thresh else "black",
            )

    # Set labels and title
    plt.xlabel("Predicted Labels")
    plt.ylabel("True Labels")
    plt.title("Confusion Matrix")
    plt.tight_layout()
    plt.show()


def evaluate(X, y, classifier, batch_size=MAXIMUM_CONCURRENT_REQUESTS):
    # Initialize lists to store the predicted and true labels
    y_true = []
    y_pred = []

    # Store results with their original index to maintain order
    results = [None] * len(X)

    # Create a ThreadPoolExecutor with limited workers
    with concurrent.futures.ThreadPoolExecutor(max_workers=batch_size) as executor:
        # Submit tasks one at a time, but executor will only run batch_size concurrently
        future_to_index = {executor.submit(classifier, x): i for i, x in enumerate(X)}

        # Process results as they complete
        for future in concurrent.futures.as_completed(future_to_index):
            index = future_to_index[future]
            predicted_label = future.result()
            results[index] = predicted_label

    # Extract predictions and true labels in order
    y_pred = results
    y_true = y

    # Normalize y_true and y_pred
    y_true = [label.strip() for label in y_true]
    y_pred = [label.strip() for label in y_pred]

    # Calculate the classification metrics
    report = classification_report(y_true, y_pred, labels=labels, zero_division=1)
    cm = confusion_matrix(y_true, y_pred, labels=labels)
    print(report)
    plot_confusion_matrix(cm, labels)

기준점: 무작위 분류기¶

성능 기준을 세우고 평가 프레임워크가 제대로 동작하는지 확인하기 위해, 티켓마다 범주를 무작위로 고르는 분류기부터 시작하겠습니다.

간단한 분류기 만들기¶

이제 Claude로 첫 실제 분류기를 만들어 보겠습니다. simple_classify 함수는 세 가지 핵심 프롬프트 엔지니어링 기법을 보여 줍니다.

  1. 구조화된 프롬프트 템플릿: 범주 정의와 지원 티켓을 명확한 XML 형식으로 제공해 Claude가 정보를 파싱하기 쉽게 만듭니다.

  2. 프리필로 출력 제어하기: assistant 응답을 <category>로 시작하고 stop_sequences=["</category>"]를 설정하면, Claude가 설명이나 부가 텍스트 없이 범주 레이블만 출력하게 됩니다. 응답 파싱이 안정적이고 결정론적이 됩니다.

  3. 결정론적 분류: temperature=0.0으로 설정하면 같은 입력에 대해 일관된 예측이 나오며, 분류 작업에서는 이것이 결정적입니다.

  1. 학습 예시 임베딩: VoyageAI 임베딩 모델로 학습 티켓 68개를 모두 벡터 임베딩으로 변환합니다
  2. 시맨틱 검색: 새 티켓마다 코사인 유사도로 가장 비슷한 학습 예시 5개를 찾습니다
  3. 프롬프트 보강: 이 유사 예시들을 분류 프롬프트에 넣어 Claude를 이끕니다

이 방식이 분류에 특히 효과적인 이유는 다음과 같습니다.

  • 비슷한 과거 예시가 의미적으로 가까운 범주를 구분하는 데 도움이 됩니다
  • 파인튜닝 없이 퓨샷 러닝으로 정확도가 올라갑니다
  • 검색이 동적이어서 질의마다 가장 관련 있는 예시를 얻습니다

VoyageAI 임베딩 모델로 임베딩 저장과 유사도 검색을 처리하는 간단한 VectorDB 클래스를 만들겠습니다.

import json
import os
import pickle

import numpy as np
import voyageai


class VectorDB:
    def __init__(self, api_key=None):
        if api_key is None:
            api_key = os.getenv("VOYAGE_API_KEY")
        self.client = voyageai.Client(api_key=api_key)
        self.embeddings = []
        self.metadata = []
        self.query_cache = {}
        self.db_path = "./data/vector_db.pkl"

    def load_data(self, data):
        # Check if the vector database is already loaded
        if self.embeddings and self.metadata:
            print("Vector database is already loaded. Skipping data loading.")
            return
        # Check if vector_db.pkl exists
        if os.path.exists(self.db_path):
            print("Loading vector database from disk.")
            self.load_db()
            return

        texts = [item["text"] for item in data]

        # Embed more than 128 documents with a for loop
        batch_size = 128
        result = [
            self.client.embed(texts[i : i + batch_size], model="voyage-2").embeddings
            for i in range(0, len(texts), batch_size)
        ]

        # Flatten the embeddings
        self.embeddings = [embedding for batch in result for embedding in batch]
        self.metadata = [item for item in data]
        self.save_db()
        # Save the vector database to disk
        print("Vector database loaded and saved.")

    def search(self, query, k=5, similarity_threshold=0.75):
        query_embedding = None
        if query in self.query_cache:
            query_embedding = self.query_cache[query]
        else:
            query_embedding = self.client.embed([query], model="voyage-2").embeddings[0]
            self.query_cache[query] = query_embedding

        if not self.embeddings:
            raise ValueError("No data loaded in the vector database.")

        similarities = np.dot(self.embeddings, query_embedding)
        top_indices = np.argsort(similarities)[::-1]
        top_examples = []

        for idx in top_indices:
            if similarities[idx] >= similarity_threshold:
                example = {
                    "metadata": self.metadata[idx],
                    "similarity": similarities[idx],
                }
                top_examples.append(example)

                if len(top_examples) >= k:
                    break
        self.save_db()
        return top_examples

    def save_db(self):
        data = {
            "embeddings": self.embeddings,
            "metadata": self.metadata,
            "query_cache": json.dumps(self.query_cache),
        }
        with open(self.db_path, "wb") as file:
            pickle.dump(data, file)

    def load_db(self):
        if not os.path.exists(self.db_path):
            raise ValueError(
                "Vector database file not found. Use load_data to create a new database."
            )

        with open(self.db_path, "rb") as file:
            data = pickle.load(file)

        self.embeddings = data["embeddings"]
        self.metadata = data["metadata"]
        self.query_cache = json.loads(data["query_cache"])

RAG로 강화한 분류기¶

이제 검색 증강 생성으로 분류기를 다시 만들어 보겠습니다. rag_classify 함수는 다음과 같이 간단한 분류기를 강화합니다.

  1. 유사 예시 검색: 티켓마다 벡터 데이터베이스에서 의미적으로 가장 비슷한 학습 예시 5개를 찾습니다
  2. 퓨샷 예시로 형식화: 이 예시들을 <query>와 <label> 태그를 사용한 XML 형식으로 구성해, 비슷한 티켓이 어떻게 분류되었는지 Claude에 보여 줍니다
  3. 프롬프트 보강: 새 티켓 분류를 요청하기 전에 이 예시들을 프롬프트에 주입합니다

이 퓨샷 러닝 방식은 비슷한 표현의 티켓이 어떻게 분류되어야 하는지 구체적인 예시로 보여 주어, Claude가 유사한 범주를 더 잘 구분하게 돕습니다. 예를 들어 테스트 티켓에 "예상치 못한 부과"가 언급되면, 과거의 "청구 이의"와 "청구 문의" 예시를 가져오는 것이 Claude가 그 미묘한 차이를 이해하는 데 도움이 됩니다.

앞선 실행에서 혼동되던 범주들의 정확도가 얼마나 개선되는지 살펴보겠습니다.

RAG에 생각의 사슬 추론 더하기¶

생각의 사슬(CoT) 프롬프팅은 분류를 결정하기 전에 Claude가 "소리 내어 생각"하게 합니다.

이 명시적인 추론 과정은 바로 분류할 때 놓칠 수 있는 미묘한 차이를 잡아내는 데 도움이 됩니다. 예를 들어 "청구서에 대해 질문이 있습니다"(청구 문의)와 "이 부과가 잘못된 것 같습니다"(청구 이의)를 구분하려면 의도와 어조를 이해해야 하는데, 단계별 분석이 여기에 도움이 됩니다.

rag_chain_of_thought_classify 함수는 Claude가 최종 <category>를 내놓기 전에 이 추론을 거치는 <scratchpad> 섹션을 추가합니다.

Promptfoo로 평가 확장하기¶

이 가이드 전반에서 프롬프트를 설계할 때 경험적 평가가 얼마나 중요한지 보여 드렸습니다. 직감에 기대는 대신 각 단계에서 성능을 측정했습니다.

  • 무작위 기준점: 약 10% → 간단한 분류기: 약 70% → RAG: 94% → RAG + CoT: 97%

이 데이터 기반 접근이 어떤 기법(RAG, 생각의 사슬)이 얼마나 가치를 더했는지 정확히 드러냈습니다. 이 방법론에 대해 더 알아보려면 프롬프트 엔지니어링 가이드를 참고하세요.

노트북을 넘어서¶

주피터 노트북은 빠른 반복과 탐색에 훌륭하지만, 프로덕션 분류 시스템에는 더 견고한 평가 인프라가 필요합니다.

  • 더 큰 테스트 세트: 68개가 아니라 수백, 수천 개 예시로 평가하고 싶어집니다
  • 여러 프롬프트 변형: 서로 다른 표현, 구조, 접근을 A/B 테스트
  • 모델 비교: 여러 Claude 모델(Haiku vs Sonnet)이나 temperature 설정에 걸친 테스트
  • 회귀 탐지: 프롬프트 변경이 실수로 정확도를 떨어뜨리지 않도록 보장
  • 버전 관리: 시스템이 발전하는 동안 프롬프트 성능을 추적

여기서 Promptfoo 같은 전용 평가 도구가 필수적이 됩니다.

Promptfoo로 하는 체계적 평가¶

위 결과는 규모 있는 체계적 프롬프트 평가의 힘을 보여 줍니다. 노트북이 개발 중 빠른 반복을 제공한 반면, Promptfoo는 여러 축에 걸쳐 프롬프트를 엄밀히 시험할 수 있게 해 주었습니다.

무엇을 시험했나¶

Promptfoo로 세 가지 프롬프트 방식(간단, RAG, RAG+CoT)을 다음 조건에서 평가했습니다.

  • 여러 temperature 설정(0.0, 0.2, 0.4, 0.6, 0.8): 결정론적 분류(T=0.0)가 약간의 무작위성이 있는 출력보다 나은지 확인
  • 동일한 테스트 세트(예시 68개): 모든 설정에서 공정한 비교 보장
  • 자동 통과/실패 판정: 각 예측을 정답 레이블과 자동으로 비교

주요 발견¶

Promptfoo 결과는 노트북에서의 발견을 확인해 주면서 추가적인 통찰도 보여 줍니다.

  1. CoT에는 temperature의 영향이 미미합니다: RAG+CoT는 T=0.0, 0.2, 0.8에서 일관되게 95.59% 정확도를 보이며, 이는 생각의 사슬 추론이 샘플링 무작위성과 무관하게 출력을 안정시킨다는 뜻입니다

  2. RAG는 temperature 변화에 강건합니다: RAG 성능이 대부분의 temperature 설정에서 89~94%로 견고하게 유지되며, T=0.0에서 가장 좋습니다(94.12%)

  3. 간단한 프롬프트는 temperature와 무관합니다: 간단한 분류기는 temperature와 관계없이 약 70% 정확도를 맴돌며, RAG나 CoT 없이는 모델이 주로 범주 정의에만 의존한다는 것을 확인해 줍니다

  4. 프로덕션 권장 사항: 최대의 일관성과 정확도(95.59%)를 위해 RAG+CoT와 함께 temperature=0.0을 사용하세요

직접 평가를 실행하려면 ./evaluation/README.md의 설정 안내를 참고하세요.
