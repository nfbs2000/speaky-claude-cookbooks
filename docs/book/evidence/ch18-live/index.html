    18장 실제 Python SDK 관찰¶

    이 페이지는 cookbook 예제를 설명하는 정적 해설이 아니라, Python Claude Agent SDK를 실제 claude-opus-5로 순차 호출해 저장한 공개 증거다. 테스트 assertion은 recorder와 projection 코드의 계약만 검증하며, 아래 판정은 raw SDK message, permission callback, host process event와 artifact snapshot 중 이 장이 실제로 발생시킨 사건에서 나왔다.

    한 번 수집하고 여러 표면에서 재생

    원전은 145개 사건이고 공개 projection은 81개다. credential, private prompt, 비공개 추론 payload, 사용자 절대 경로는 공개하지 않았다. 공개 사건은 source event ID와 SHA-256을 유지한다.

    중요한 판정 규칙은 다음과 같다.

    • 관찰됨: 기대 사건과 순서가 이번 raw evidence에 직접 존재한다.
    • 설정됨: host가 입력과 실행 조건을 고정했지만 server 동작을 뜻하지는 않는다.
    • 추론됨: 관찰값과 통제 조건이 해석을 지지하지만 직접 event가 없는 경우다.
    • 관찰되지 않음: 이번 event surface와 workload에서 확인하지 못한 주장이다.
    • 수정 필요: 같은 버전·설정·도구 범위에서 책 문장과 직접 충돌할 때만 사용한다.
    • 추가 관측 필요: 사건을 유도하지 않았거나 범위가 달라 이번 실행만으로 판단할 수 없다.
    • 따라서 관찰하지 못했다는 사실만으로 책이 틀렸다고 판정하지 않는다.

    공개 경계¶

    • hook-cases-configured: 세 replay attempt는 requested Opus 5, provider concurrency 1, include_hook_events true, whole-tool-allowed controlled MCP target을 사용했다. 두 rewrite attempt에는 PreToolUse matcher 두 개와 PostToolUse matcher 한 개를, deny attempt에는 PreToolUse deny matcher 한 개를 등록했다.
    • python-hook-surface-configured: Python Agent SDK 0.2.128 HookEvent 타입은 PreToolUse, PostToolUse, PostToolUseFailure, UserPromptSubmit, Stop, SubagentStop, PreCompact, Notification, SubagentStart, PermissionRequest의 10개 literal을 선언한다.
    • same-event-hooks-dispatched-concurrently: 두 callback이 서로의 진입을 기다리는 barrier를 모두 통과했으므로 이 버전과 이 event 구성에서는 같은 event의 matcher가 concurrent dispatch된 것으로 해석한다. 모든 hook 종류와 버전에 일반화하지 않는다.
    • hook-order-is-not-a-pipeline: 같은 event의 여러 HookMatcher를 등록 순서대로 실행되는 상태 변환 pipeline으로 설명하면 안 된다. 이 표본에서는 두 callback이 함께 진입하고 역순으로 반환했다.
    • mcp-rewrite-wrapper-is-invalid-here: updatedMCPToolOutput에 content 필드를 가진 object를 넣는 예시는 이 CLI에서 유효하지 않았다. content block 배열 자체는 성공했지만 현재 타입은 가능한 경우 updatedToolOutput을 선호하라고 설명한다.
    • include-hook-events-is-not-guaranteed-callback-tape: include_hook_events true만으로 Python callback의 hook_started와 hook_response가 항상 SDK output stream에 나온다고 가르치면 안 된다. 두 callback run에서 lifecycle message는 0개였다.
    • hook-progress-is-not-current-python-phase: Python SDK 0.2.128 HookEventMessage 타입은 hook_started와 hook_response를 문서화하며 hook_progress class 또는 phase는 찾지 못했다.
    • model-narrative-is-not-handler-proof: 모델 최종문은 handler 내부 실행을 볼 수 없다고 정확히 제한했다. 반대로 모델이 handler가 실행 또는 미실행했다고 말하더라도 host process record 없이 실행 사실을 증명할 수 없다.
    • terminal-success-does-not-mean-every-tool-succeeded: terminal Result success를 모든 tool call의 성공으로 해석하면 안 된다. malformed rewrite와 explicit deny 모두 error ToolResult가 있었지만 terminal subtype은 success였다.
    • init-model-is-not-response-model-proof: 실험 코드가 System init의 model만 actual_model로 사용하면 fallback 또는 synthetic message를 놓친다. 실제 모델 판정은 AssistantMessage.model의 단일성으로 해야 한다.
