    6장 실제 Python SDK 관찰¶

    이 페이지는 cookbook 예제를 설명하는 정적 해설이 아니라, Python Claude Agent SDK를 실제 claude-opus-5로 순차 호출해 저장한 공개 증거다. 테스트 assertion은 recorder와 projection 코드의 계약만 검증하며, 아래 판정은 raw SDK message, permission callback, host process event와 artifact snapshot 중 이 장이 실제로 발생시킨 사건에서 나왔다.

    한 번 수집하고 여러 표면에서 재생

    원전은 685개 사건이고 공개 projection은 171개다. credential, private prompt, 비공개 추론 payload, 사용자 절대 경로는 공개하지 않았다. 공개 사건은 source event ID와 SHA-256을 유지한다.

    중요한 판정 규칙은 다음과 같다.

    • 관찰됨: 기대 사건과 순서가 이번 raw evidence에 직접 존재한다.
    • 수정 필요: 같은 버전·설정·도구 범위에서 책 문장과 직접 충돌할 때만 사용한다.
    • 추가 관측 필요: 사건을 유도하지 않았거나 범위가 달라 이번 실행만으로 판단할 수 없다.
    • 따라서 관찰하지 못했다는 사실만으로 책이 틀렸다고 판정하지 않는다.

    무효 시도¶

    • 102504-21ef5772: 모델은 target.py를 최소 수정했지만 probe가 존재하지 않는 python 명령만 허용해 python3 검증이 permission에 막혔다. 모델 행동 주장의 성공 사례에서 제외하고 harness 수정 근거로 보존한다. 이 시도는 invalid attempt다.

    같은 증거를 보는 공개 표면¶

    표면 시각화 관점
    Agent Flow · ch06 실행 원인, tool use/result, permission, claim 경계
    Runtime City · ch06 실행 OTel 시간축, 실행 zone, Observed/Missing

    Hypnagonia · Observation Ordeal 검증 주장, 선택, 관찰 consequence

    각 표면은 같은 JSON을 무작정 복제한 것이 아니다. Agent Flow는 원인·도구·결과를, Runtime City는 시간축과 실행 구역을, Pixel Agents는 actor 상태를, Observation Ordeal은 주장·선택·결과를 표현한다. 어느 renderer도 raw evidence의 판정을 바꿀 수 없다.

    공개 경계¶

    • invalid-python-rule-was-a-harness-defect: 첫 실행은 python 명령 부재와 python3 permission 불일치로 max turns에 도달했다. 이 실패를 모델의 범위 제어 실패나 성공으로 세면 안 된다.
    • primary-opus-is-not-only-provider-usage: assistant와 subagent의 primary model은 Opus 5였지만 각 성공 Result의 model_usage에는 Haiku 4.5 보조 사용도 기록됐다. provider 사용 전체를 Opus뿐이라고 쓰면 안 된다.
    • prompt-general-probability-shift-needs-controls: 여섯 단발 실행은 각 과제의 행동을 보여 주지만 프롬프트가 일반적 행동 확률을 얼마나 바꿨는지는 무지침 대조군과 반복 실행이 필요하다.
    • permission-card-click-not-observed: host can_use_tool request와 deny는 관찰됐지만 제품 UI 카드 표시와 사람의 버튼 클릭은 이 SDK 실행에 없다.
    • dedicated-tool-statistical-preference-needs-repetition: 이번 과제에서는 Bash 없이 전용 도구를 썼지만 지침이 선택 확률을 일반적으로 높였다는 결론은 반복 대조 실험 전에는 내리지 않는다.

    • numeric-anchor-stability-needs-distribution: 2개 문서와 80단어 제한은 한 번 충족됐지만 정성 지침보다 안정적이라는 주장은 여러 독립 실행의 분포가 필요하다.
