    18b장 실제 Python SDK 관찰¶

    이 페이지는 cookbook 예제를 설명하는 정적 해설이 아니라, Python Claude Agent SDK를 실제 claude-opus-5로 순차 호출해 저장한 공개 증거다. 테스트 assertion은 recorder와 projection 코드의 계약만 검증하며, 아래 판정은 raw SDK message, permission callback, host process event와 artifact snapshot 중 이 장이 실제로 발생시킨 사건에서 나왔다.

    한 번 수집하고 여러 표면에서 재생

    원전은 115개 사건이고 공개 projection은 51개다. credential, private prompt, 비공개 추론 payload, 사용자 절대 경로는 공개하지 않았다. 공개 사건은 source event ID와 SHA-256을 유지한다.

    중요한 판정 규칙은 다음과 같다.

    • 관찰됨: 기대 사건과 순서가 이번 raw evidence에 직접 존재한다.
    • 설정됨: host가 입력과 실행 조건을 고정했지만 server 동작을 뜻하지는 않는다.
    • 추론됨: 관찰값과 통제 조건이 해석을 지지하지만 직접 event가 없는 경우다.
    • 관찰되지 않음: 이번 event surface와 workload에서 확인하지 못한 주장이다.
    • 수정 필요: 같은 버전·설정·도구 범위에서 책 문장과 직접 충돌할 때만 사용한다.
    • 추가 관측 필요: 사건을 유도하지 않았거나 범위가 달라 이번 실행만으로 판단할 수 없다.
    • 따라서 관찰하지 못했다는 사실만으로 책이 틀렸다고 판정하지 않는다.

    • sandbox-pair-configured: 두 attempt는 requested Opus 5, provider concurrency 1, Bash 단일 tool, autoAllowBashIfSandboxed true, allowUnsandboxedCommands false, excludedCommands empty를 사용했고 enabled만 false와 true로 나눴다.

    • sandbox-caused-boundary-difference-in-pair: 두 독립 temp session의 의도적 구성 차이는 sandbox enabled였고 같은 command 형태와 marker를 사용했으므로, 이 통제 pair의 sibling write 차이는 sandbox 경계 효과로 해석한다. 모든 경로와 버전에 일반화하지 않는다.
    • terminal-success-is-not-subcommand-success: terminal Result success를 command 내부 모든 subcommand 성공으로 해석하면 안 된다. enabled run은 sibling redirect가 실패했지만 마지막 printf 때문에 success로 끝났다.
    • toolresult-nonerror-is-not-side-effect-proof: ToolResultBlock.is_error false만으로 모든 파일 side effect를 확정하면 안 된다. host readback은 enabled sibling 파일이 없음을 보여 줬다.
    • model-narrative-is-not-file-proof: 모델은 파일을 별도로 읽지 않았다고 제한했다. 모델 서술의 확신 여부와 무관하게 실제 file side effect는 process 종료 뒤 host readback으로 판정해야 한다.
