    15장 실제 Python SDK 관찰¶

    이 페이지는 cookbook 예제를 설명하는 정적 해설이 아니라, Python Claude Agent SDK를 실제 claude-opus-5로 순차 호출해 저장한 공개 증거다. 테스트 assertion은 recorder와 projection 코드의 계약만 검증하며, 아래 판정은 raw SDK message, permission callback, host process event와 artifact snapshot 중 이 장이 실제로 발생시킨 사건에서 나왔다.

    한 번 수집하고 여러 표면에서 재생

    원전은 60개 사건이고 공개 projection은 47개다. credential, private prompt, 비공개 추론 payload, 사용자 절대 경로는 공개하지 않았다. 공개 사건은 source event ID와 SHA-256을 유지한다.

    중요한 판정 규칙은 다음과 같다.

    • 관찰됨: 기대 사건과 순서가 이번 raw evidence에 직접 존재한다.
    • 설정됨: host가 입력과 실행 조건을 고정했지만 server 동작을 뜻하지는 않는다.
    • 추론됨: 관찰값과 통제 조건이 해석을 지지하지만 직접 event가 없는 경우다.
    • 관찰되지 않음: 이번 event surface와 workload에서 확인하지 못한 주장이다.
    • 수정 필요: 같은 버전·설정·도구 범위에서 책 문장과 직접 충돌할 때만 사용한다.
    • 추가 관측 필요: 사건을 유도하지 않았거나 범위가 달라 이번 실행만으로 판단할 수 없다.
    • 따라서 관찰하지 못했다는 사실만으로 책이 틀렸다고 판정하지 않는다.

    Runtime City · ch15 실행 OTel 시간축, 실행 zone, Observed/Missing
    Pixel Agents · ch15 증거 actor와 tool lifecycle 상태
    Hypnagonia · Observation Ordeal 검증 주장, 선택, 관찰 consequence

    각 표면은 같은 JSON을 무작정 복제한 것이 아니다. Agent Flow는 원인·도구·결과를, Runtime City는 시간축과 실행 구역을, Pixel Agents는 actor 상태를, Observation Ordeal은 주장·선택·결과를 표현한다. 어느 renderer도 raw evidence의 판정을 바꿀 수 없다.

    공개 경계¶

    • v2-prefix-triple-configured: Host는 fresh attempt nonce를 공유하는 8,190-character system prompt 세 개를 만들고 stable-a/control은 byte-identical, volatile-b는 index 41 timestamp 한 글자만 다르게 설정했다. 새 SDK client/config directory 세 개를 concurrency 1로 실행했다.
    • timestamp-change-is-strong-miss-candidate: 같은 시도 안에서 byte-identical control은 2,629 read를 기록하고 index 41 한 글자 변경군은 read 0을 기록했으므로 앞쪽 timestamp 변경이 이 표본의 miss를 설명하는 가장 강한 통제 후보다. Server cause event는 없어 인과 확정은 아니다.
    • control-read-mostly-maps-to-stable-prefix: Control의 read 2,629와 create 130은 baseline create 2,755와 비슷한 총량이고 host 차이는 latest user marker뿐이어서 안정 prefix 대부분의 재사용을 지지한다. Provider token-to-byte map은 없어 attribution은 추론이다.
    • messages-cache-control-and-ttft-are-not-agent-options: Messages API cookbook의 cache_control과 stream TTFT를 ClaudeAgentOptions 기능으로 설명하면 안 된다. 이 Agent SDK probe는 Result usage를 수집했지만 provider cache-attributed TTFT를 수집하지 않았다.
    • empty-settings-do-not-remove-builtins: setting_sources와 tools를 비웠다는 사실을 built-in agent, skill, slash command도 없다는 뜻으로 설명하면 안 된다. 실제 init에는 세 표면이 존재했다.
    • captured-is-not-cache-pass: OTel CAPTURED, assertion count 0, verdict TODO, passed null은 raw 수집 완료와 수동 판독 대기 상태이지 cache 주장의 자동 pass가 아니다.
    • primary-model-is-not-only-provider-usage: 세 init의 primary model이 Opus 5여도 terminal model_usage에 Haiku 4.5가 있으므로 전체 provider usage를 Opus 하나로 표현하면 안 된다.
    • otel-is-not-independent-provider-proof: 같은 recorder가 raw SDK와 process event를 OTel로 투영했으므로 sequence 일치는 recorder 무손실 확인이지 독립 provider 관측 증거가 아니다.
    • one-triple-is-not-general-cost-speed-quality-proof: 한 controlled triple의 실제 usage와 cost 차이만으로 일반 비용 절감률, 속도 향상, 결과 품질 변화를 증명했다고 쓰면 안 된다.
    • provider-cache-key-and-breakpoint-not-observed: Provider cache key, breakpoint, eviction reason과 system byte가 cache token segment에 대응하는 방식은 SDK event에서 관찰되지 않았다.
    • provider-ttft-and-ttl-not-observed: 이 Agent SDK probe는 provider cache-attributed TTFT와 실제 TTL 만료 경계를 관찰하지 않았다.
    • dynamic-list-cache-effect-not-observed: Init에서 agent, skill, slash command 목록을 보았지만 세 run 사이에서 위치나 크기를 바꾸지 않았으므로 해당 목록의 cache 효과는 관찰하지 않았다.
    • path-skill-budget-conditional-relocation-not-observed: Absolute path placeholder, skill/document budget, conditional paragraph prefix/suffix 위치의 효과는 이번 timestamp case에서 실행하지 않았다.
    • quality-and-repeat-distribution-not-observed: Exact marker 과제는 일반 결과 품질 비교가 아니며 한 triple은 latency, cost, hit-rate의 반복 분포를 만들기에 부족하다.
    • candidate-pattern-pairs-required: Path raw/placeholder, skill budget, conditional paragraph prefix/suffix를 각각 한 변수만 바꾸는 별도 sequential pair가 필요하다.
    • repeated-sequential-samples-required: Cache 패턴의 안정성을 말하려면 fresh nonce를 사용하는 같은 triple을 더 반복하되 provider concurrency 1을 유지해야 한다.

    • messages-api-ttft-and-ttl-case-required: Explicit cache_control, streaming TTFT, 실제 TTL을 가르치려면 Agent SDK 실험과 섞지 않고 Messages API cookbook 계열의 별도 실제 실행이 필요하다.
