    8f장 실제 Python SDK 관찰¶

    이 페이지는 cookbook 예제를 설명하는 정적 해설이 아니라, Python Claude Agent SDK를 실제 claude-opus-5로 순차 호출해 저장한 공개 증거다. 테스트 assertion은 recorder와 projection 코드의 계약만 검증하며, 아래 판정은 raw SDK message, permission callback, host process event와 artifact snapshot 중 이 장이 실제로 발생시킨 사건에서 나왔다.

    한 번 수집하고 여러 표면에서 재생

    원전은 661개 사건이고 공개 projection은 77개다. credential, private prompt, 비공개 추론 payload, 사용자 절대 경로는 공개하지 않았다. 공개 사건은 source event ID와 SHA-256을 유지한다.

    중요한 판정 규칙은 다음과 같다.

    • 관찰됨: 기대 사건과 순서가 이번 raw evidence에 직접 존재한다.
    • 수정 필요: 같은 버전·설정·도구 범위에서 책 문장과 직접 충돌할 때만 사용한다.
    • 추가 관측 필요: 사건을 유도하지 않았거나 범위가 달라 이번 실행만으로 판단할 수 없다.
    • 따라서 관찰하지 못했다는 사실만으로 책이 틀렸다고 판정하지 않는다.

    Agent Flow · ch08f 실행 원인, tool use/result, permission, claim 경계
    Runtime City · ch08f 실행 OTel 시간축, 실행 zone, Observed/Missing
    Pixel Agents · ch08f 증거 actor와 tool lifecycle 상태
    Hypnagonia · Observation Ordeal 검증 주장, 선택, 관찰 consequence

    각 표면은 같은 JSON을 무작정 복제한 것이 아니다. Agent Flow는 원인·도구·결과를, Runtime City는 시간축과 실행 구역을, Pixel Agents는 actor 상태를, Observation Ordeal은 주장·선택·결과를 표현한다. 어느 renderer도 raw evidence의 판정을 바꿀 수 없다.

    공개 경계¶

    • can-use-tool-is-not-a-universal-observer: allow rule, acceptEdits, bypassPermissions가 callback보다 먼저 결정할 수 있으므로 can_use_tool만으로 전체 permission audit를 만들면 누락된다.
    • programmatic-host-decision-is-not-human-ui: 8f allow/deny는 host program이 반환했으며 실제 사람이 permission card를 클릭한 증거가 아니다.
    • tool-denial-is-not-run-failure: deny와 dontAsk는 error ToolResult와 denial을 남겼지만 terminal Result 자체는 success였다.
    • auto-rationale-is-not-observed: auto에서 handler가 실행된 사실은 classifier prompt, reason, matched rule의 증거가 아니다.
    • auto-final-misnames-tool-handler: auto assistant final은 permission handler 실행을 주장하지만 host permission callback은 0이고 실제 process record는 tool handler 실행이다.
    • primary-opus-is-not-only-provider-usage: 다섯 init과 primary assistant는 Opus 5지만 Result model_usage에는 Haiku 4.5 보조 사용도 있다.
    • captured-is-not-claim-pass: CAPTURED와 assertion count 0은 raw 수집 완료 표식이지 permission 주장 합격 판정이 아니다.
    • shadow-warning-is-host-sdk-not-provider-event: CanUseToolShadowedWarning은 Python SDK가 낸 host warning이며 provider stream event로 세면 안 된다.
    • permission-ui-lanes-are-not-peer-sdk-messages: AskUserQuestion, permission control request, MCP elicitation, denial evidence는 UI lane이지 네 동급 top-level SDKMessage class가 아니다.
    • probe-runtime-definition-is-not-fully-provenance-bound: manifest는 장 source와 prompt hash를 묶지만 exact probe/runtime/tool definition/handler source를 모두 묶지 않았다.
    • tool-annotation-causality-is-not-proven: destructive/open-world annotation은 host source에서 확인되지만 raw init에 annotation receipt가 없어 permission 결과의 단독 원인으로 선언하지 않는다.
    • actor-user-record-is-not-human-click-proof: 4b host approval record의 actor=user 문자열만으로 실제 인간 UI 승인이라고 주장할 수 없다.
    • external-permission-tool-routing-not-observed: permission_prompt_tool_name의 SDK source 계약은 확인했지만 실제 external permission tool 왕복은 실행하지 않았다.
    • project-instruction-classifier-causality-not-observed: setting_sources가 빈 실행에서 CLAUDE.md가 auto classifier에 미친 인과를 관찰하지 않았다.
    • human-permission-card-action-not-observed: 실제 사용자가 권한 카드 버튼을 누른 UI receipt와 SDK callback 결합은 아직 없다.
    • permission-rule-matcher-precedence-not-observed: exact/prefix/wildcard matcher와 실제 settings-file allow의 전체 우선순위는 실행하지 않았다.
    • ask-and-elicitation-ui-lanes-not-observed: AskUserQuestion과 MCP elicitation을 실제로 발생시킨 UI lane 실행은 이 증거 묶음에 없다.

    • full-source-provenance-not-observed: exact probe/runtime/tool description/annotation/handler source를 모두 attempt에 암호학적으로 묶는 provenance가 필요하다.
