    17장 실제 Python SDK 관찰¶

    이 페이지는 cookbook 예제를 설명하는 정적 해설이 아니라, Python Claude Agent SDK를 실제 claude-opus-5로 순차 호출해 저장한 공개 증거다. 테스트 assertion은 recorder와 projection 코드의 계약만 검증하며, 아래 판정은 raw SDK message, permission callback, host process event와 artifact snapshot 중 이 장이 실제로 발생시킨 사건에서 나왔다.

    한 번 수집하고 여러 표면에서 재생

    원전은 123개 사건이고 공개 projection은 47개다. credential, private prompt, 비공개 추론 payload, 사용자 절대 경로는 공개하지 않았다. 공개 사건은 source event ID와 SHA-256을 유지한다.

    중요한 판정 규칙은 다음과 같다.

    • 관찰됨: 기대 사건과 순서가 이번 raw evidence에 직접 존재한다.
    • 설정됨: host가 입력과 실행 조건을 고정했지만 server 동작을 뜻하지는 않는다.
    • 추론됨: 관찰값과 통제 조건이 해석을 지지하지만 직접 event가 없는 경우다.
    • 관찰되지 않음: 이번 event surface와 workload에서 확인하지 못한 주장이다.
    • 수정 필요: 같은 버전·설정·도구 범위에서 책 문장과 직접 충돌할 때만 사용한다.
    • 추가 관측 필요: 사건을 유도하지 않았거나 범위가 달라 이번 실행만으로 판단할 수 없다.
    • 따라서 관찰하지 못했다는 사실만으로 책이 틀렸다고 판정하지 않는다.

    무효 시도¶

    • 없음

    같은 증거를 보는 공개 표면¶

    표면 시각화 관점
    Agent Flow · ch17 실행 원인, tool use/result, permission, claim 경계
    Runtime City · ch17 실행 OTel 시간축, 실행 zone, Observed/Missing
    Pixel Agents · ch17 증거 actor와 tool lifecycle 상태
    Hypnagonia · Observation Ordeal 검증 주장, 선택, 관찰 consequence

    각 표면은 같은 JSON을 무작정 복제한 것이 아니다. Agent Flow는 원인·도구·결과를, Runtime City는 시간축과 실행 구역을, Pixel Agents는 actor 상태를, Observation Ordeal은 주장·선택·결과를 표현한다. 어느 renderer도 raw evidence의 판정을 바꿀 수 없다.

    공개 경계¶

    • two-auto-cases-configured: 두 case는 새 temp workspace, config와 SDK session, actual Opus 5, provider concurrency 1을 사용했다. 첫 case는 deny callback을 구성했고, 둘째 case는 primary explicit deny와 fallback whole-tool allow를 구성했다.
    • auto-resolved-before-host-callback-for-this-request: 첫 case에서 deny callback이 구성됐는데 callback 0, handler 1, denial 0이므로 이 요청은 host callback에 도달하기 전에 auto 경로에서 허용된 것으로 해석된다. 내부 함수 순서를 직접 본 것은 아니다.
    • auto-is-not-a-fail-closed-guarantee: auto mode가 destructive-annotated tool을 항상 ask 또는 deny해 fail-closed를 보장한다고 설명하면 안 된다. 이 side-effect-free 통제 요청은 callback 없이 실제 handler까지 실행됐다.
    • can-use-tool-is-not-universal-observer: can_use_tool 하나를 모든 tool 실행의 보편 감사 지점으로 설명하면 누락이 생긴다. 첫 case는 callback 0인데 primary handler가 실행됐고 둘째 explicit deny도 callback 없이 처리됐다.
    • fallback-was-not-autonomous-policy-discovery: 둘째 fallback을 모델의 자율적 안전 정책 발견으로 설명하면 안 된다. 사용자 prompt가 primary가 거부될 때만 fallback을 정확히 1회 호출하라고 실행 전에 지정했다.
    • model-annotation-attribution-is-unsupported: 모델 최종문의 annotation 기반 gate 추정은 host evidence보다 약하다. 실제 manifest 원인은 primary explicit disallowed_tools였고 permission error에는 내부 rule rationale가 없었다.
    • safe-whitelist-is-design-not-runtime-contract: Read는 auto, destructive는 ask/deny 같은 표를 auto mode의 보장된 runtime whitelist로 제시하면 안 된다. 그 표는 host가 구현할 제품 정책 예시다.
    • otel-is-not-independent-provider-proof: OTel span은 같은 recorder가 raw SDK와 process event를 투영한 결과이므로 sequence 일치는 수집기의 무손실 확인이지 독립 provider 증거가 아니다.
    • probe-source-was-not-cryptographically-bound: 이 과거 CH17 manifest의 source_hash는 실행 당시 chapter bytes만 가리키며 probe, case와 runtime Python source hash를 함께 묶지 않았다. 실행 원본 파일은 남아 있지만 코드 전체가 manifest에 암호학적으로 귀속됐다고 말할 수 없다.
    • internal-auto-rationale-not-observed: auto classifier의 내부 prompt, confidence, allow/ask/deny 기준과 이 요청을 허용한 구체적 rationale는 SDK stream에 나타나지 않았다.
    • annotation-causal-effect-not-observed: 두 case의 annotation을 한 변수로 통제해 비교하지 않았으므로 destructiveHint가 auto 허용 또는 explicit deny에 끼친 인과 효과는 관찰되지 않았다.
    • real-user-ask-ui-not-observed: 실제 사람이 승인 또는 거절하는 permission UI, ask 상태와 외부 permission.reply 경로는 이 두 비대화형 SDK 실행에 없다.
    • general-auto-policy-not-observed: built-in tool 전체, 실제 외부 mutation, 다양한 input과 managed policy에 대한 auto의 일반 동작은 controlled MCP 두 표본으로 증명되지 않았다.
    • current-cli-replication-required: 공개 실행은 Claude Code 2.1.220에서 수집됐다. 현재 설치된 2.1.221의 동작을 주장하려면 같은 probe, prompt, SDK와 정책을 고정한 순차 재실행이 필요하다.

    • human-ask-and-built-in-matrix-required: ask UI와 callback 왕복, built-in Read/Edit/Bash별 auto 경계, annotation만 바꾼 인과 비교는 각각 독립 session과 한 변수 통제로 추가 관찰해야 한다.
