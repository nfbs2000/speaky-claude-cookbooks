    3장 실제 Python SDK 관찰¶

    이 페이지는 cookbook 예제를 설명하는 정적 해설이 아니라, Python Claude Agent SDK를 실제 claude-opus-5로 순차 호출해 저장한 공개 증거다. 테스트 assertion은 recorder와 projection 코드의 계약만 검증하며, 아래 판정은 raw SDK message, permission callback, host process event와 artifact snapshot 중 이 장이 실제로 발생시킨 사건에서 나왔다.

    한 번 수집하고 여러 표면에서 재생

    원전은 104개 사건이고 공개 projection은 43개다. credential, private prompt, 비공개 추론 payload, 사용자 절대 경로는 공개하지 않았다. 공개 사건은 source event ID와 SHA-256을 유지한다.

    관찰 판정¶

    claim 판정 실제 관찰 또는 경계 첫 source ref
    persistent-client-preserves-session-context 관찰됨 동일 ClaudeSDKClient의 두 turn은 같은 session ID를 유지했고, 두 번째 결과가 첫 turn에만 주입한 controlled nonce를 반환했다. attempt:045357-39114649:sdk-message:2
    init-reemits-per-client-turn 관찰됨 현재 Python SDK와 CLI 조합에서는 같은 client의 다음 질의에도 SystemMessage.init이 다시 방출됐다. init은 session 전체에서 한 번뿐인 사건이 아니다. attempt:045357-39114649:sdk-message:2
    stateless-query-opens-independent-sessions 관찰됨 독립 query 두 번은 서로 다른 session ID를 만들었고, 두 번째 결과에는 첫 query의 controlled nonce가 없었다. attempt:045504-b1bb05a0:sdk-message:2
    tool-result-precedes-max-turn-terminal 관찰됨 max_turns=1에서도 Assistant tool_use, Python handler 실행, UserMessage tool_result가 끝난 뒤 error_max_turns와 num_turns=2인 ResultMessage가 종료했다. attempt:050250-58c61dd6:sdk-message:16
    five-core-loop-roles-appear-in-tape 관찰됨 한 max-turn run에서 SystemMessage, StreamEvent, AssistantMessage, UserMessage, ResultMessage가 같은 session의 순차 evidence tape로 나타났다. attempt:050250-58c61dd6:sdk-message:2
    five-core-roles-are-not-complete-message-union 범위 수정 필요 세 Python run에는 RateLimitEvent도 실제 방출됐다. 다섯 메시지는 강의의 핵심 역할이지 SDK 전체 Message union이 아니다. attempt:045357-39114649:sdk-message:4
    hook-surface-is-language-and-version-specific 범위 수정 필요 Python SDK 0.2.128 HookEvent는 10종이고 TypeScript SDK 0.3.177 표면은 더 넓다. SessionStart, PostCompact, PermissionDenied 등을 공통 Python 목록으로 쓰면 안 된다. python-sdk:0.2.128:types.py:HookEvent:sha256:de495a6fa20136b0dd0528865e94c5f429eef5ad5ba197e214a2e597e4601e2a
    compact-resume-recovery-and-hook-runtime 추가 관측 필요 resume, compact boundary, max output/budget/structured-output terminal 경로와 실제 hook lifecycle 순서는 별도 순차 live run이 필요하다. spec:claims:compact-resume-recovery-and-hook-runtime

    중요한 판정 규칙은 다음과 같다.

    • 관찰됨: 기대 사건과 순서가 이번 raw evidence에 직접 존재한다.
    • 수정 필요: 같은 버전·설정·도구 범위에서 책 문장과 직접 충돌할 때만 사용한다.
    • 추가 관측 필요: 사건을 유도하지 않았거나 범위가 달라 이번 실행만으로 판단할 수 없다.
    • 따라서 관찰하지 못했다는 사실만으로 책이 틀렸다고 판정하지 않는다.

    공개 경계¶

    • five-core-roles-are-not-complete-message-union: 세 Python run에는 RateLimitEvent도 실제 방출됐다. 다섯 메시지는 강의의 핵심 역할이지 SDK 전체 Message union이 아니다.
    • hook-surface-is-language-and-version-specific: Python SDK 0.2.128 HookEvent는 10종이고 TypeScript SDK 0.3.177 표면은 더 넓다. SessionStart, PostCompact, PermissionDenied 등을 공통 Python 목록으로 쓰면 안 된다.

    • compact-resume-recovery-and-hook-runtime: resume, compact boundary, max output/budget/structured-output terminal 경로와 실제 hook lifecycle 순서는 별도 순차 live run이 필요하다.

    • 공개 JSON: ch03-live.json
