    19장 실제 Python SDK 관찰¶

    이 페이지는 cookbook 예제를 설명하는 정적 해설이 아니라, Python Claude Agent SDK를 실제 claude-opus-5로 순차 호출해 저장한 공개 증거다. 테스트 assertion은 recorder와 projection 코드의 계약만 검증하며, 아래 판정은 raw SDK message, permission callback, host process event와 artifact snapshot 중 이 장이 실제로 발생시킨 사건에서 나왔다.

    한 번 수집하고 여러 표면에서 재생

    원전은 46개 사건이고 공개 projection은 62개다. credential, private prompt, 비공개 추론 payload, 사용자 절대 경로는 공개하지 않았다. 공개 사건은 source event ID와 SHA-256을 유지한다.

    중요한 판정 규칙은 다음과 같다.

    • 관찰됨: 기대 사건과 순서가 이번 raw evidence에 직접 존재한다.
    • 설정됨: host가 입력과 실행 조건을 고정했지만 server 동작을 뜻하지는 않는다.
    • 추론됨: 관찰값과 통제 조건이 해석을 지지하지만 직접 event가 없는 경우다.
    • 관찰되지 않음: 이번 event surface와 workload에서 확인하지 못한 주장이다.
    • 수정 필요: 같은 버전·설정·도구 범위에서 책 문장과 직접 충돌할 때만 사용한다.
    • 추가 관측 필요: 사건을 유도하지 않았거나 범위가 달라 이번 실행만으로 판단할 수 없다.
    • 따라서 관찰하지 못했다는 사실만으로 책이 틀렸다고 판정하지 않는다.

    공개 경계¶

    • setting-source-surface-configured: Python Agent SDK 0.2.128의 SettingSource는 user, project, local이고 ClaudeAgentOptions.setting_sources는 None, 빈 list, 선택 source list를 구분한다. 문서상 None은 CLI 기본 source, []는 filesystem setting 비활성, project는 CLAUDE.md 로드 조건이다.
    • controlled-pair-configured: 두 attempt는 같은 chapter bytes, probe source hashes, Opus 5, Read 단일 tool, 동일 CLAUDE.md와 evidence marker, provider concurrency 1을 사용하고 setting_sources만 []와 [project]로 나눴다.
    • safe-readonly-prompt-configured: 프롬프트는 disposable temporary workspace의 읽기 전용 marker 과업으로 제한했고, loaded instruction이 명시하지 않은 경로 탐색과 관련 없는 작업을 금지했다. 보안 우회나 권한 상승은 요청하지 않았다.
    • project-source-caused-pair-difference: 동일한 임시 파일, tool surface, prompt와 모델에서 의도적으로 바꾼 변수는 setting_sources였고 memoryFiles와 실제 행동이 함께 갈라졌으므로, 이 통제 pair에서는 project source 활성화를 차이의 원인으로 해석한다. 모든 source 조합에 일반화하지 않는다.
    • host-file-presence-is-not-load-proof: CLAUDE.md가 두 workspace에 모두 존재했다는 사실만으로 load를 확정하면 안 된다. empty pair는 같은 파일이 있어도 memoryFiles가 비어 있었다.
    • model-self-report-is-not-load-proof: 모델이 지침을 읽었다고 서술하는지 여부는 load 증명이 아니다. current SDK에서는 memoryFiles inventory와 실제 tool/result를 우선해야 한다.
    • init-model-is-not-response-model-proof: System init.model은 configured model이다. 보안 거부 뒤 lower-model fallback을 놓치지 않으려면 actual model은 AssistantMessage.model의 단일성으로 판정해야 한다.
    • context-usage-model-is-not-response-model-proof: get_context_usage().model도 context 계산 대상 모델이지 응답 메시지 자체의 모델 증거로 대체하지 않는다.
    • opus-response-is-not-opus-only-provider-run: 모든 AssistantMessage가 Opus 5였다는 관찰을 provider run 전체가 Opus만 사용했다는 말로 확대하면 안 된다. Result model_usage에는 Haiku 보조 사용량도 있었다.
    • memory-files-is-not-security-boundary: memoryFiles에 CLAUDE.md가 나타나는 것은 context load 증거이지 permission, hook 또는 sandbox 강제를 뜻하지 않는다. CLAUDE.md는 모델 지침이다.
    • instructions-loaded-is-not-current-hook: InstructionsLoaded를 Python SDK 0.2.128 HookEvent literal 또는 이번 stream의 실제 event로 가르치면 안 된다.
    • config-change-is-not-current-hook: ConfigChange를 Python SDK 0.2.128 HookEvent literal 또는 이번 stream의 실제 event로 가르치면 안 된다.
    • file-changed-is-not-current-hook: FileChanged를 Python SDK 0.2.128 HookEvent literal 또는 이번 stream의 실제 event로 가르치면 안 된다.
