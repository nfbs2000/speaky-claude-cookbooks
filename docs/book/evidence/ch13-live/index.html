    13장 실제 Python SDK 관찰¶

    이 페이지는 cookbook 예제를 설명하는 정적 해설이 아니라, Python Claude Agent SDK를 실제 claude-opus-5로 순차 호출해 저장한 공개 증거다. 테스트 assertion은 recorder와 projection 코드의 계약만 검증하며, 아래 판정은 raw SDK message, permission callback, host process event와 artifact snapshot 중 이 장이 실제로 발생시킨 사건에서 나왔다.

    한 번 수집하고 여러 표면에서 재생

    원전은 36개 사건이고 공개 projection은 38개다. credential, private prompt, 비공개 추론 payload, 사용자 절대 경로는 공개하지 않았다. 공개 사건은 source event ID와 SHA-256을 유지한다.

    중요한 판정 규칙은 다음과 같다.

    • 관찰됨: 기대 사건과 순서가 이번 raw evidence에 직접 존재한다.
    • 설정됨: host가 입력과 실행 조건을 고정했지만 server 동작을 뜻하지는 않는다.
    • 추론됨: 관찰값과 통제 조건이 해석을 지지하지만 직접 event가 없는 경우다.
    • 관찰되지 않음: 이번 event surface와 workload에서 확인하지 못한 주장이다.
    • 수정 필요: 같은 버전·설정·도구 범위에서 책 문장과 직접 충돌할 때만 사용한다.
    • 추가 관측 필요: 사건을 유도하지 않았거나 범위가 달라 이번 실행만으로 판단할 수 없다.
    • 따라서 관찰하지 못했다는 사실만으로 책이 틀렸다고 판정하지 않는다.

    무효 시도¶

    • 114239-0c0565f2: run A는 cache creation을 기록했지만 run B가 provider overload retry 뒤 완료되지 않아 pair 증거로 채택하지 않았다. 이 시도는 invalid attempt다.

    같은 증거를 보는 공개 표면¶

    표면 시각화 관점
    Agent Flow · ch13 실행 원인, tool use/result, permission, claim 경계
    Runtime City · ch13 실행 OTel 시간축, 실행 zone, Observed/Missing

    각 표면은 같은 JSON을 무작정 복제한 것이 아니다. Agent Flow는 원인·도구·결과를, Runtime City는 시간축과 실행 구역을, Pixel Agents는 actor 상태를, Observation Ordeal은 주장·선택·결과를 표현한다. 어느 renderer도 raw evidence의 판정을 바꿀 수 없다.

    공개 경계¶

    • v2-prefix-and-isolation-configured: host는 7,806-character V2 prefix, 서로 다른 A/B suffix, 두 새 SDK client, 빈 tool/settings surface, fallback 없음, provider concurrency 1을 설정했다.
    • read-tokens-map-to-stable-prefix-mostly: B의 read 2,427과 creation 143 합이 A creation 2,570과 같고 host 입력 차이는 suffix뿐이므로 long prefix 대부분의 reuse를 강하게 지지한다. server segment-to-byte map은 없어 attribution은 추론이다.
    • messages-cache-control-is-not-agent-option: Messages API cookbook의 cache_control을 설치된 Python ClaudeAgentOptions field로 설명하면 안 된다. Agent SDK 실험은 system prompt와 Result usage 표면을 사용했다.
    • host-prefix-hash-is-not-full-server-key: host가 기록한 system prompt hash는 통제 입력 증거이지 전체 server cache key 구성 증거가 아니다.
    • cache-scope-attribution-not-observed: raw SDK와 terminal usage에는 global 또는 org cache scope attribution이 없다.
    • ttl-expiry-boundary-not-observed: usage의 ephemeral_1h field 이름은 관찰했지만 시간 경계를 넘겨 호출하지 않아 실제 만료 시점은 관찰하지 못했다.
    • latency-causality-not-observed: 한 A/B pair는 반복 latency 분포가 아니므로 cache가 일반 latency 개선을 일으켰다는 인과를 관찰하지 못했다.
    • mcp-tool-schema-cache-break-not-observed: tool과 MCP surface가 비어 있었으므로 schema 변경이 깨뜨리는 cache segment는 이번 run에서 관찰하지 못했다.
    • primary-opus-is-not-only-provider-usage: primary assistant init은 Opus 5지만 terminal model_usage에는 Haiku 4.5도 있으므로 전체 provider usage를 Opus 하나로 표현하면 안 된다.
    • captured-is-not-cache-claim-pass: OTel CAPTURED, assertion count 0, verdict TODO, passed null은 raw 수집 완료와 수동 판독 대기 상태이지 cache 주장의 자동 pass가 아니다.
    • otel-is-not-independent-provider-proof: 같은 recorder가 raw SDK와 process event를 OTel로 투영했으므로 trace를 독립 provider 관측기로 부르면 안 된다.
    • ttl-boundary-sweep-required: 5분과 1시간 전후의 동일 prefix를 순차 호출해 실제 expiry boundary를 측정하는 별도 장시간 case가 필요하다.
    • repeated-latency-cost-sample-required: cache usage와 latency/cost의 분포를 분리하려면 같은 조건의 반복 sequential sample이 필요하다.
    • tool-mcp-schema-ab-required: tool 또는 MCP schema 하나만 바꾸는 A/B에서 cache read segment 변화를 측정해야 schema-break 주장을 검증할 수 있다.

    • preset-variants-required: string system prompt와 preset append/exclude_dynamic_sections의 cache 차이는 별도 controlled case가 필요하다.
