    12장 실제 Python SDK 관찰¶

    이 페이지는 cookbook 예제를 설명하는 정적 해설이 아니라, Python Claude Agent SDK를 실제 claude-opus-5로 순차 호출해 저장한 공개 증거다. 테스트 assertion은 recorder와 projection 코드의 계약만 검증하며, 아래 판정은 raw SDK message, permission callback, host process event와 artifact snapshot 중 이 장이 실제로 발생시킨 사건에서 나왔다.

    한 번 수집하고 여러 표면에서 재생

    원전은 124개 사건이고 공개 projection은 51개다. credential, private prompt, 비공개 추론 payload, 사용자 절대 경로는 공개하지 않았다. 공개 사건은 source event ID와 SHA-256을 유지한다.

    중요한 판정 규칙은 다음과 같다.

    • 관찰됨: 기대 사건과 순서가 이번 raw evidence에 직접 존재한다.
    • 수정 필요: 같은 버전·설정·도구 범위에서 책 문장과 직접 충돌할 때만 사용한다.
    • 추가 관측 필요: 사건을 유도하지 않았거나 범위가 달라 이번 실행만으로 판단할 수 없다.
    • 따라서 관찰하지 못했다는 사실만으로 책이 틀렸다고 판정하지 않는다.

    표면 시각화 관점
    Agent Flow · ch12 실행 원인, tool use/result, permission, claim 경계
    Runtime City · ch12 실행 OTel 시간축, 실행 zone, Observed/Missing
    Pixel Agents · ch12 증거 actor와 tool lifecycle 상태
    Hypnagonia · Observation Ordeal 검증 주장, 선택, 관찰 consequence

    각 표면은 같은 JSON을 무작정 복제한 것이 아니다. Agent Flow는 원인·도구·결과를, Runtime City는 시간축과 실행 구역을, Pixel Agents는 actor 상태를, Observation Ordeal은 주장·선택·결과를 표현한다. 어느 renderer도 raw evidence의 판정을 바꿀 수 없다.

    공개 경계¶

    • single-point-is-not-exact-50k-boundary: 60,082-character 한 지점의 외부화는 exact 50,000-character threshold를 확정하지 않는다.
    • aggregate-200k-limit-not-observed: 같은 turn에서 여러 tool result를 합산하는 workload를 실행하지 않았으므로 200K aggregate limit을 관찰 사실로 쓸 수 없다.
    • characters-bytes-repr-and-tokens-differ: 이번 ASCII artifact의 bytes와 characters가 같아도 character, byte, Python representation, API token은 서로 다른 단위다. host ToolResult는 실제 text 340, representation 376이다.
    • sdk-files-persisted-event-is-not-current-python-type: Python Agent SDK 0.2.128은 SDKFilesPersistedEvent를 export하지 않고 두 run에도 전용 persisted SystemMessage가 없다.
    • overflow-text-is-not-run-failure: overflow notice의 Error prefix를 ToolResult error flag 또는 terminal run failure와 합치면 안 된다.
    • model-attribution-is-not-host-ownership-proof: runtime final의 host tool policy attribution은 handler가 write하지 않았다는 controlled process evidence와 충돌하므로 소유권 증거로 쓰지 않는다.
    • exact-internal-writer-is-not-observed: controlled handler 뒤와 model ToolResult 앞의 pipeline 외부화는 관찰했지만 전용 event가 없어 숨은 내부 writer component는 특정하지 않는다.
    • host-self-report-is-not-disk-proof: preview의 path/hash 자기보고가 아니라 host process event와 capture-time disk read-back이 persistence를 증명한다.
    • thinking-estimate-is-not-terminal-usage: thinking_tokens의 estimated_tokens는 stream 추정 신호이며 terminal API input/output usage나 billing count가 아니다.
    • primary-opus-is-not-only-provider-usage: primary assistant model은 Opus 5지만 두 terminal model_usage에는 Haiku 4.5도 있어 전체 provider usage를 Opus 하나로 쓰면 안 된다.
    • two-run-usage-difference-is-not-general-savings: 두 independent run의 usage 차이에는 answer 길이와 cache 상태가 섞여 있어 persisted-preview의 일반 비용 절감률로 확대할 수 없다.
    • captured-is-not-claim-pass: OTel CAPTURED, assertion count 0, verdict TODO, passed null은 raw 수집 완료와 수동 판독 대기 상태이며 threshold claim pass가 아니다.
    • otel-is-not-independent-provider-proof: 같은 recorder가 raw SDK와 process event를 OTel로 투영했으므로 OTel을 독립 provider 관측기로 부르면 안 된다.
    • public-projection-must-redact-runtime-identifiers: runtime overflow text의 로컬 절대경로와 session identifier는 private read-back에만 필요하며 공개 projection에는 content hash와 redacted label만 남긴다.
    • exact-boundary-sweep-not-observed: 49K/50K/51K와 서로 다른 token density payload를 순차 실행해 exact boundary와 governing unit를 찾아야 한다.
    • aggregate-budget-pressure-not-observed: 같은 turn의 여러 tool result가 만드는 aggregate budget pressure는 별도 controlled workload가 필요하다.
    • runtime-spill-lifecycle-not-observed: runtime 원본 spill file이 session 또는 process cleanup 뒤 얼마나 유지되는지는 관찰하지 않았다.
    • messages-api-count-token-comparison-not-observed: cookbook의 Messages API count_tokens와 Agent SDK runtime usage를 같은 실행 계약으로 비교하는 별도 API-family 실험이 필요하다.
    • repeated-cost-latency-distribution-not-observed: 한 쌍의 run은 benchmark가 아니므로 preview 정책의 cost와 latency 분포는 반복 표본이 필요하다.

    • unicode-unit-separation-not-observed: Unicode payload로 byte, character, serialized representation, token 단위가 갈라지는 실행을 추가해야 한다.

    • 공개 JSON: ch12-live.json
