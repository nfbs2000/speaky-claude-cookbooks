# 30장: 나만의 AI 에이전트 만들기 - 실행 계약으로 닫는 MVP

> 공개 GitHub Pages 투영판: [30장: 나만의 AI 에이전트 만들기](https://nfbs2000.github.io/speaky-claude-cookbooks/book/part7/ch30/)

마지막 장의 목표는 Claude Code를 복제하는 것이 아닙니다. 앞 장에서 다룬 프롬프트, 도구,
권한, 세션, 메모리, 옵저버빌리티를 **하나의 재현 가능한 실행 계약**으로 묶는 것입니다.

모델이 그럴듯한 최종 문장을 출력했다는 사실만으로 에이전트가 완성되지는 않습니다. 실제 도구
핸들러가 실행됐는지, 거부한 작업이 실행되지 않았는지, 파일이 남았는지, 새 클라이언트가 같은
세션을 재개했는지, raw 사건이 OTel에 누락 없이 투영됐는지를 따로 확인해야 합니다.

이 장은 실제 `claude-opus-5` 두 턴을 순차 실행해 다음 질문을 검증합니다.

> 로컬 보고서와 외부 메모리를 만들고, 외부 게시를 권한 단계에서 거부하고, 새 클라이언트가
> 같은 세션을 재개해 그 메모리를 실제 도구로 다시 읽는 작은 에이전트를 만들 수 있는가?

## 30.1 실제 실행 계약

이번 MVP의 범위는 의도적으로 작습니다.

```text
turn 1
  inspect_request        read-only, 사전 허용
  -> save_local_report   mutation, host allow
  -> publish_external    destructive, host deny
  -> save_memory         mutation, host allow
  -> terminal Result

turn 2: 새 ClaudeSDKClient(resume=session_id)
  load_memory            read-only, 사전 허용
  -> terminal Result

각 단계
  -> raw SDK/callback/host event
  -> bounded OTel span
  -> deterministic judge
  -> integrity snapshot
```

- accepted attempt: `153528-a47425f8`
- OTel trace: `6540d007a831261473a7c5b5115283f6`
- session: `d8c93c59-3209-48d7-a73b-b6f655f287c3`
- SDK: Python `claude-agent-sdk==0.2.128`
- CLI: `2.1.220`
- actual init model: 두 턴 모두 `claude-opus-5`
- provider concurrency: 1

## 30.2 에이전트는 API 래퍼가 아니라 실행 경계다

이번 실행은 다음 계층을 분리했습니다.

| 계층 | 책임 | 이번 실행의 증거 |
| --- | --- | --- |
| 요청 계약 | 모델이 수행할 순서와 완료 marker | host prompt + hash |
| runtime | 실제 SDK client와 session lifecycle | init/Result/session ID |
| tool contract | 입력 schema와 실제 handler | ToolUse/ToolResult/process event |
| permission gate | mutation allow, external deny | permission callback |
| artifact | 모델 밖에 남는 결과와 메모리 | `report.md`, `memory.json` hash |
| raw recorder | 공개 SDK·callback·host 사건 보존 | JSONL sequence |
| projector | raw 사건을 bounded OTel로 변환 | 한 trace의 carrier span |
| judge | 순서·부재·파일 상태를 독립 판정 | 9개 deterministic check |

이 경계에서 actor는 모델과 도구를 실행합니다. projector는 사건을 OTel로 옮기고, judge는 저장된
사건과 파일 상태를 다시 읽어 판정합니다. 모델에게 자신의 성공 여부를 채점하게 하지 않습니다.

## 30.3 Python SDK의 실제 메시지 계약

Python SDK 0.2.128은 `SDKMessage`라는 이름을 export하지 않습니다. 공개 메시지 타입은
`Message` union이며 `SystemMessage`, `AssistantMessage`, `UserMessage`, `ResultMessage`,
`StreamEvent`, `RateLimitEvent`를 포함합니다.

```python
from claude_agent_sdk import ClaudeAgentOptions, ClaudeSDKClient, Message

options = ClaudeAgentOptions(
    model="claude-opus-5",
    permission_mode="default",
    can_use_tool=decide_permission,
    mcp_servers={"agent_lab": server},
    allowed_tools=[INSPECT_TOOL, LOAD_MEMORY_TOOL],
    include_partial_messages=True,
    include_hook_events=True,
)

async with ClaudeSDKClient(options=options) as client:
    await client.query(turn1_prompt)
    async for message in client.receive_response():
        archive_raw(message)
```

TypeScript SDK의 `SDKMessage` 이름과 Python의 `Message` union을 같은 API처럼 섞으면 안 됩니다.
또한 `linked_claim`, `evidence_level`, `evaluation`은 SDK 원본 필드가 아니라 projector와 judge가
만드는 파생 필드입니다.

## 30.4 읽기 허용과 mutation 권한을 구분한다

이번 옵션은 읽기 전용 두 도구만 `allowed_tools`에 넣었습니다.

```python
allowed_tools = [INSPECT_TOOL, LOAD_MEMORY_TOOL]

async def decide_permission(tool_name, tool_input, context):
    if tool_name == PUBLISH_TOOL:
        return PermissionResultDeny(
            message="HOST_DENY_EXTERNAL_PUBLISH",
            interrupt=False,
        )
    if tool_name in {REPORT_TOOL, SAVE_MEMORY_TOOL}:
        return PermissionResultAllow(updated_input=tool_input)
    return PermissionResultDeny(message="HOST_DENY_UNEXPECTED_TOOL")
```

실제 callback 기록은 이 구분과 일치했습니다.

| sequence | 도구 | 관찰 |
| ---: | --- | --- |
| 15 -> 18 | `inspect_request` | 사전 허용, callback 없이 실제 result |
| 35 -> 36 -> 40 -> 41 | `save_local_report` | requested, allow, handler, result |
| 54 -> 55 -> 59 | `publish_external` | requested, deny, error ToolResult |
| 73 -> 74 -> 76 -> 77 | `save_memory` | requested, allow, handler, result |
| 99 -> 100 -> 105 | `load_memory` | 사전 허용, 실제 handler와 result |

중요한 판정은 “모델이 거부를 인정했다”가 아닙니다. `publish_external`의 실행 process event가
0개이고 host artifact state의 `external_publish_count`도 0인 것이 근거입니다. 거부된
ToolResult seq 59 뒤에도 세션은 중단되지 않았고, 모델은 허용된 `save_memory`를 계속 수행해
turn 1을 정상 종료했습니다. **개별 도구 거부와 전체 턴 실패는 같은 상태가 아닙니다.**

## 30.5 파일 산출물은 모델 문장과 별도로 확인한다

도구 핸들러는 임시 workspace에 결정적인 파일을 만들었습니다.

```text
report.md
  sha256 049b9e14caac44e12d50cee6586d1aeabe0087465f98514f40bcfc08443009e2
  marker 포함: true

memory.json
  {"marker": "<run marker>", "report_path": "report.md"}
  sha256 b6fd6ba6f56783cd993746513db778bebdf2b8bd9e8d3f78fc62a78e1102504a

external_publish_count
  0
```

turn 1 뒤 seq 90과 turn 2 뒤 seq 116의 artifact snapshot은 정확히 같았습니다. 따라서 두 번째
턴이 메모리를 읽는 동안 보고서나 메모리를 몰래 바꾸지 않았고, 외부 게시도 발생하지 않았다고
판정할 수 있습니다.

이 실험의 workspace는 증거 캡처용 임시 공간이므로 제품의 영구 저장소를 증명하지 않습니다.
증명한 것은 **호스트가 관찰한 파일 생성·내용·해시·불변성**입니다.

## 30.6 세션 재개와 외부 메모리는 서로 다른 증거다

turn 1의 성공 `ResultMessage` seq 89에서 session ID를 얻은 뒤 첫 번째 client를 닫았습니다.
그 다음 새 options에 `resume=session_id`를 넣어 새 `ClaudeSDKClient`를 만들었습니다.

```python
session_id = turn1_result.session_id
resumed = build_options(..., resume=session_id)

async with ClaudeSDKClient(options=resumed) as client:
    await client.query(turn2_prompt)
    async for message in client.receive_response():
        archive_raw(message)
```

두 init seq 2와 92, 두 Result seq 89와 115는 모두 같은 session ID를 가졌습니다. 이것은
session resume의 직접 증거입니다.

그러나 “같은 세션이므로 모델이 기억했다”라고 판정하지 않았습니다. 두 번째 prompt는 대화
기억으로 답하지 말고 `load_memory`를 호출하라고 요구했습니다. 실제 handler seq 100이
`memory.json`을 읽었고 ToolResult seq 105가 marker와 `report.md` 경로를 돌려준 뒤에만 최종
marker seq 111이 나왔습니다.

```text
Result(turn 1) seq 89
  -> init(resume, same session) seq 92
  -> ToolUse(load_memory) seq 99
  -> host memory-read seq 100
  -> ToolResult(MEMORY_LOADED) seq 105
  -> assistant confirmation seq 111
  -> Result(turn 2) seq 115
```

세션 연속성은 SDK runtime의 증거이고, 외부 메모리 회수는 파일과 도구 실행의 증거입니다. 둘을
합쳐 설명할 수는 있지만 같은 것으로 취급하면 안 됩니다.

## 30.7 성공 Result도 비용과 범위를 함께 읽는다

두 턴 모두 실제 성공 Result였습니다.

| 턴 | duration | turns | cost | terminal marker |
| ---: | ---: | ---: | ---: | --- |
| 1 | `22,349ms` | 5 | `$0.034939` | `TURN1_COMPLETE` |
| 2 | `8,487ms` | 2 | `$0.0088325` | `TURN2_MEMORY_CONFIRMED` |
| 합계 | `30,836ms` | 7 | `$0.0437715` | 두 Result 성공 |

init에는 두 턴 모두 Opus 5가 기록됐습니다. billing에는 Opus 5와 Haiku label이 있었지만,
Haiku가 어떤 내부 역할을 맡았는지는 공개 사건에 없으므로 추정하지 않습니다.

## 30.8 raw와 OTel 완전성

judge가 읽은 frozen actor scope는 sequence `0..117`의 raw 사건 118개와 OTel span 122개입니다.
모든 raw sequence에 carrier가 있었고 missing은 0개이며 span은 모두 trace
`6540d007a831261473a7c5b5115283f6`에 속했습니다.

raw와 span 수가 다른 것은 오류가 아닙니다. 실제 도구 실행 process event 4개는 각각
`process.event`와 `tool.execution` 두 관점을 만들었습니다.

```text
118 raw events
  + 4 tool.execution projection views
  = 122 frozen-scope spans
```

freeze 뒤 `sdk.capture.finished`, verdict, root attempt span이 추가된 최종 archive는 raw
119개와 OTel 125개입니다. actor scope와 사후 bookkeeping 범위를 섞어 count equality를
주장하지 않습니다.

최종 `integrity.json` 대상 8개를 디스크에서 다시 해시했고 모두 일치했습니다.

## 30.9 독립 판정 9개

이번 judge는 다음 조건을 모두 통과해야만 `OBSERVED`로 판정했습니다.

1. 두 성공 Result와 두 init이 같은 resumed session ID를 가진다.
2. request inspection이 mutation보다 먼저 실제 완료된다.
3. host allow 뒤에만 local report handler가 실행된다.
4. external publish는 deny 뒤 handler가 실행되지 않는다.
5. 거부 뒤 host allow를 받아 external memory artifact를 저장한다.
6. memory ToolResult 뒤에 turn 1 완료 문구와 Result가 나온다.
7. 새 client의 resumed turn이 실제 memory handler와 ToolResult를 거친다.
8. 두 턴 뒤 artifact snapshot이 같고 external publish count가 0이다.
9. frozen raw sequence 전체에 OTel carrier가 있다.

이것은 한 제어된 로컬 에이전트 계약을 증명합니다. 다음 항목은 이번 실행에서 증명하지
않았습니다.

| 항목 | 판정 |
| --- | --- |
| 임의의 사용자 업무를 일반적으로 해결한다 | not observed |
| 메모리에서 자동으로 장기 학습한다 | not observed |
| 외부 서비스에 실제 게시한다 | 의도적으로 denied |
| 원격 서버에 배포·호스팅한다 | not observed / TODO |
| Genkit projection을 실행한다 | not observed / TODO |
| Opik remote evaluation을 저장한다 | not observed / TODO |
| 비정상 종료·resume failure를 복구한다 | not observed / TODO |
| 여러 provider run을 병렬 처리한다 | 금지; concurrency 1 |

## 30.10 제품으로 확장하는 순서

1. 한 요청과 한 산출물을 가진 작은 tool contract부터 고정합니다.
2. 읽기 전용, 로컬 mutation, 외부 destructive action을 permission policy로 분리합니다.
3. SDK message, permission callback, host execution, artifact snapshot을 같은 sequence 공간에
   저장합니다.
4. 모델 문장이 아니라 ToolResult와 host state로 성공·거부·부재를 판정합니다.
5. session resume와 외부 memory load를 별개 check로 둡니다.
6. raw sequence에서 OTel carrier로 가는 projection coverage를 감사합니다.
7. 실패·중단·재시도·중복 실행 실험을 추가한 뒤에만 서비스 범위를 넓힙니다.
8. Genkit, Opik, Book Canvas 같은 소비자는 raw 계약이 안정된 뒤 붙입니다.

## 30.11 학생 실습

```text
실제 Claude Agent SDK로 로컬 에이전트 하나를 만든다.

1. 읽기 도구 1개, 로컬 쓰기 도구 1개, 외부 위험 도구 1개를 정의한다.
2. 읽기는 사전 허용하고, 로컬 쓰기는 callback allow, 외부 작업은 callback deny한다.
3. ToolUse, permission decision, handler, ToolResult를 raw JSONL에 저장한다.
4. 허용된 로컬 파일은 hash로 검증하고 거부된 handler는 실행 0건인지 검사한다.
5. 첫 Result의 session ID로 새 client를 resume한다.
6. 두 번째 턴은 외부 memory 파일을 실제 도구로 읽은 뒤에만 답하게 한다.
7. frozen raw event의 OTel carrier 누락을 검사한다.
8. 관찰하지 않은 기능은 성공으로 쓰지 말고 TODO로 남긴다.
```

## Takeaway

나만의 AI 에이전트는 모델 호출을 감싼 함수가 아닙니다. 요청, 런타임, 도구, 권한, 산출물,
세션, 메모리, raw 사건, projection, 판정을 서로 대조할 수 있는 실행 시스템입니다.

가장 중요한 원칙은 간단합니다. 모델의 설명을 증거로 대신하지 말고, 실제 ToolResult와 호스트
상태를 보존하세요. 그리고 실행하지 않은 것은 실행했다고 쓰지 마세요.
